  • ⚡
    6× mais quota diária que o 70b O tier gratuito do Groq aloca muito mais tokens por dia para modelos 8b, reduzindo drasticamente rate limits em produção.
  • ⏱
    Inferência significativamente mais rápida Com a arquitetura de chips LPU do Groq, o 8b responde em ~400ms contra ~2s do 70b — melhor UX percebida no frontend.
  • 🎯
    Qualidade adequada para RAG com contexto restrito O pipeline envia apenas 3 chunks rerankeados ao LLM. Com contexto bem delimitado, o 8b performa de forma equivalente ao 70b na tarefa de geração de resposta.
  • 💰
    Sem custo adicional no tier free Ambos os modelos Groq são gratuitos, mas o 8b tem limites de tokens por dia muito superiores — menos interrupções sem aumentar custo.
02 · Cascata de fallback

Como funciona quando algo falha

Passo 1 — Tentativa principal
llama-3.1-8b-instant
Groq · primário
Falha? Rate limit ou erro de servidor → próximo
Passo 2 — Retry Groq
llama-3.1-8b-instant
Groq · segunda tentativa
Falha? Qualquer erro → próximo
Passo 3 — Fallback final (provider diferente)
llama-3.3-70b

Falha? HTTPException 502 retornada ao cliente

04 · Implementação

Lógica de cascata no código

src/rag_query.py 
def generate_answer_with_fallback(prompt: str) -> str:
    """Cascata: Groq 8b → Groq 8b (retry) → Cerebras 70b."""

    # Tentativa 1 — modelo primário (Groq 8b)
    try:
        return generate_answer(prompt, model=config.GROQ_LLM_MODEL)
    except Exception:
        pass  # captura rate limits, erros de servidor, chave ausente

    # Tentativa 2 — retry no mesmo provider
    try:
        return generate_answer(prompt, model=config.GROQ_LLM_FAST)
    except Exception:
        pass

    # Tentativa 3 — provider independente (Cerebras)
    # Se falhar, propaga → HTTPException 502 em app.py
    return _generate_cerebras(prompt)
